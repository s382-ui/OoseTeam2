# 서브시스템 검증 시나리오

작성일: 2026-06-19

## 목적

연구실 안전관리 시스템의 화면, API, 입력 검증, JSON 저장 동작을 서브시스템별로 확인하기 위한 수동 인수 테스트 문서다.

## 사전 준비

1. 백엔드와 프론트엔드를 종료한다.
2. 반복 가능한 초기 상태가 필요하면 `backend/data`를 삭제한다.
3. 다음 명령으로 백엔드와 프론트엔드를 각각 실행한다.

```powershell
cd C:\Projects\OoseTeam2\backend
$env:GRADLE_USER_HOME="C:\gradle-home"
.\gradlew.bat bootRun
```

```powershell
cd C:\Projects\OoseTeam2\frontend
npm start
```

4. 브라우저에서 `http://localhost:3000`에 접속한다.
5. 시나리오는 사용자 → 연구실 → 화학물질 → 폐기물 → 일상점검 → 점검 → 안전교육 순서로 실행한다.

## 공통 판정 기준

- 등록 성공 후 성공 메시지가 표시된다.
- 조회 탭에서 새 데이터가 즉시 확인된다.
- 잘못된 요청은 HTTP 400과 이해 가능한 오류 메시지를 반환한다.
- 브라우저 새로고침 후에도 등록 결과가 유지된다.

## 1. 사용자 관리

### USR-01 사용자 단건 등록 및 조회

입력 데이터:

| 항목 | 값 |
|---|---|
| 사용자 ID | `verify-user-01` |
| 성명 | `검증사용자` |
| 소속 | `안전공학과` |
| 역할 | `연구원` |
| 연락처 | `010-1111-2222` |
| 이메일 | `verify.user01@example.com` |
| 계정 상태 | `활성` |

절차:

1. 사용자 관리의 `등록` 탭에서 입력 데이터를 등록한다.
2. `조회` 탭에서 사용자 ID `verify-user-01`을 검색한다.
3. 결과 행의 `상세`를 선택한다.

예상 결과:

- 등록 완료 메시지가 표시된다.
- 조회 결과가 1건이며 입력한 정보가 상세 영역에 표시된다.

### USR-02 중복 사용자 ID 차단

절차:

1. USR-01과 같은 사용자 ID로 다시 등록한다.

예상 결과:

- 등록되지 않는다.
- `이미 사용 중인 ID입니다: verify-user-01` 메시지가 표시된다.

### USR-03 CSV 대량 등록

CSV 데이터:

```csv
userId,userName,department,role,contact,email,accountStatus
verify-bulk-01,대량검증1,화학공학과,연구원,010-2000-0001,bulk01@example.com,활성
verify-bulk-02,대량검증2,화학공학과,대학원생,010-2000-0002,bulk02@example.com,활성
```

절차:

1. `대량 등록` 탭에서 양식을 내려받거나 위 내용으로 UTF-8 CSV를 만든다.
2. CSV를 선택하고 미리보기 행 수를 확인한다.
3. `일괄 등록`을 선택한다.
4. 조회 탭에서 `verify-bulk`를 검색한다.

예상 결과:

- 업로드 검증 결과가 2행으로 표시된다.
- 두 사용자가 모두 등록된다.
- 같은 CSV를 다시 등록하면 전체 요청이 중단되고 중복 ID 메시지가 표시된다.

## 2. 연구실 관리

### LAB-01 연구실 등록 및 조건 조회

선행 조건: `verify-user-01` 사용자가 등록되어 있어야 한다.

입력 데이터:

| 항목 | 값 |
|---|---|
| 연구실 ID | `VERIFY-LAB-01` |
| 연구실명 | `안전검증 연구실` |
| 건물명 | `공학2관` |
| 층 | `4` |
| 호실 | `401` |
| 소속 | `안전공학과` |
| 책임자 ID | `verify-user-01` |
| 책임자명 | `검증사용자` |
| 연락처 | `02-1111-2222` |
| 관리 등급 | `A` |
| 사용 여부 | `사용` |

절차:

1. 연구실 관리에서 입력 데이터를 등록한다.
2. 조회 탭에서 건물명 `공학2관`과 책임자명 `검증사용자`를 입력한다.
3. 상세 정보를 연다.

예상 결과:

- 조건에 맞는 연구실 1건이 조회된다.
- 책임자와 위치 정보가 등록값과 일치한다.

### LAB-02 존재하지 않는 책임자 차단

절차:

1. 새 연구실 ID를 입력한다.
2. 책임자 ID에 `missing-user`를 입력하고 등록한다.

예상 결과:

- `등록되지 않은 연구실 책임자 ID입니다: missing-user` 메시지가 표시된다.
- 연구실이 저장되지 않는다.

### LAB-03 연구실 위치 중복 차단

절차:

1. 연구실 ID와 연구실명만 새 값으로 변경한다.
2. 건물명 `공학2관`, 층 `4`, 호실 `401`은 LAB-01과 동일하게 입력한다.
3. 등록한다.

예상 결과:

- 같은 위치의 활성 연구실이 있다는 메시지가 표시된다.
- 중복 연구실이 저장되지 않는다.

## 3. 화학물질 관리

### CHM-01 화학물질 등록 및 상세 조회

입력 데이터:

| 항목 | 값 |
|---|---|
| 화학물질 ID | `VERIFY-CHEM-01` |
| 제조사명 | `검증화학` |
| 화학물질명 | `메탄올` |
| CAS 번호 | `67-56-1` |
| 성분 함유량 | `99.9%` |
| MSDS 경로 | `msds/verify-methanol.pdf` |
| 성분분석표 경로 | `analysis/verify-methanol.pdf` |
| 상태 | `정상` |

절차:

1. 화학물질 관리에서 입력 데이터를 등록한다.
2. 조회 탭에서 제조사명 `검증화학` 또는 CAS 번호 `67-56-1`로 검색한다.
3. 상세 정보를 확인한다.

예상 결과:

- 화학물질 1건이 조회된다.
- 함유량과 문서 경로가 상세 영역에 표시된다.

### CHM-02 CAS 번호 중복 차단

절차:

1. 화학물질 ID를 `VERIFY-CHEM-02`로 변경한다.
2. CAS 번호는 `67-56-1`로 유지해 등록한다.

예상 결과:

- `이미 등록된 CAS 번호입니다: 67-56-1` 메시지가 표시된다.

### CHM-03 상태 조건 조회

절차:

1. 상태 필터를 `정상`으로 선택한다.
2. CHM-01 데이터가 조회되는지 확인한다.

예상 결과:

- 정상 상태 필터가 적용된다.
- `VERIFY-CHEM-01`이 조회 결과에 포함된다.

## 8. 최종 회귀 검증

모든 서브시스템 검증 후 다음을 확인한다.

1. 각 메뉴를 이동해도 다른 서브시스템의 목록과 폼 상태가 비정상적으로 섞이지 않는다.
2. 브라우저 새로고침 후 등록 데이터가 유지된다.
3. 백엔드를 재시작해도 `backend/data`의 등록 데이터가 유지된다.
4. 안전교육 메뉴와 API가 비안전교육 변경 이후에도 정상 동작한다.
5. 다음 빌드가 모두 성공한다.

```powershell
cd C:\Projects\OoseTeam2\backend
$env:GRADLE_USER_HOME="C:\gradle-home"
.\gradlew.bat clean test build --no-daemon
```
