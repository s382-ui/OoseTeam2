# 연구실 안전관리 시스템 구현 리뷰

작성일: 2026-06-11

## 프로젝트 개요

이 프로젝트는 React 18과 Create React App 기반의 연구실 안전관리 시스템 프로토타입이다. 백엔드, 라우터, 전역 상태 관리, 영속 저장소 없이 각 화면 컴포넌트가 `useState`로 등록, 조회, 검색, 삭제 흐름을 처리한다.

현재 구현은 다음 업무 영역을 사이드바 메뉴로 제공한다.

- 사용자 관리: 사용자 등록, 역할/부서 기반 조회, 계정 상태 표시
- 연구실 관리: 연구실 등록, 건물/부서 기반 조회, 관리등급과 사용 여부 표시
- 화학물질 관리: 화학물질 등록, 제조사/CAS 번호 기반 조회, MSDS 존재 여부 표시
- 폐기물 관리: 폐기물 분류 등록, 유형 기반 조회, 처리 방법과 관련 법규 표시
- 일상점검/체크리스트 관리: 체크리스트 항목 등록, 점검 유형/필수 여부/사용 여부 표시
- 점검 관리: 점검분야 분류 등록, 사용 여부 기반 조회
- 안전교육 관리: 연구활동종사자/이수기준, 안전교육일지, 수료증 발급, 학습 결과, 교육이수 결과 하위 화면 제공

## 아키텍처

`src/App.jsx`가 사이드바 메뉴 상태를 관리하고, `pageMap`을 통해 현재 선택된 업무 컴포넌트를 렌더링한다. 각 업무 컴포넌트는 내부에서 등록 탭과 조회 탭을 전환하며, 폼 상태, 목록 데이터, 검색 조건, 알림 메시지를 독립적으로 관리한다.

공통 UI 스타일은 `src/App.css`에 집중되어 있다. 레이아웃, 사이드바, 탭, 카드, 폼, 버튼, 검색바, 테이블, 배지, 알림 스타일이 전역 클래스 형태로 정의되어 있어 모든 관리 화면이 동일한 시각 언어를 사용한다.

## 구현 패턴

각 관리 화면은 대체로 같은 패턴을 따른다.

1. `initForm` 또는 초기 폼 객체를 정의한다.
2. `tab`, `form`, `data`, `search`, `alert` 상태를 둔다.
3. `handleSubmit`에서 필수값을 확인하고 신규 행을 목록 앞에 추가한다.
4. 등록 성공 시 폼을 초기화하고 3초짜리 성공 알림을 표시한다.
5. 조회 탭에서는 검색 조건으로 `data`를 필터링한다.
6. 테이블 행의 삭제 버튼으로 해당 항목을 메모리 상태에서 제거한다.

이 패턴은 프로토타입 단계에서 빠르게 업무 화면을 늘리기에 적합하다. 다만 도메인별 검증, 저장소 연결, 중복 코드 제거가 필요한 단계로 넘어가면 공통 훅 또는 데이터 서비스 계층을 도입하는 것이 좋다.

## 현재 한계

- 새로고침 시 모든 등록 데이터가 사라진다.
- 서버 API, 데이터베이스, 인증/권한, 감사 로그가 없다.
- 컴포넌트별 CRUD 코드가 반복되어 유지보수 비용이 커질 수 있다.
- 필수값 검증은 최소 수준이며, ID 중복, 날짜 범위, 숫자 범위, 이메일/전화번호 형식 검증이 부족하다.
- 삭제 확인 절차가 없어 실수로 항목을 제거할 수 있다.
- 자동 테스트 구성이 없다.
- 접근성 검증이 부족하다. 예를 들어 일부 탭/버튼 상태는 시각적으로는 구분되지만 ARIA 속성은 없다.
- `SafetyEducationManagement.jsx`는 여러 하위 업무가 한 파일에 모여 있어 파일 크기와 책임 범위가 커졌다.

## 개선 권장사항

우선순위가 높은 개선은 다음과 같다.

1. 데이터 영속화: 임시 단계에서는 `localStorage`, 실제 서비스 단계에서는 REST API 또는 Firebase/Supabase 같은 백엔드 저장소를 연결한다.
2. 공통 CRUD 추상화: 등록/조회/삭제/검색/알림 패턴을 공통 훅으로 분리한다.
3. 검증 강화: ID 중복, 숫자 범위, 날짜 순서, 이메일/전화번호 형식, 필수값 메시지를 명확히 한다.
4. 테스트 추가: React Testing Library로 메뉴 전환, 등록, 검색, 삭제 플로우를 검증한다.
5. 안전교육 화면 분리: 하위 섹션을 별도 컴포넌트 파일로 나눠 변경 범위를 줄인다.
6. 문서 업데이트 의무화: 기능 변경 시 구현 문서와 에이전트 작업 기록을 함께 갱신한다.

## 테스트 제안

현재 테스트 정보가 없으므로 다음 두 가지 테스트를 우선 추가한다.

- 메뉴 전환 테스트: 사이드바에서 각 메뉴 버튼을 클릭했을 때 대응하는 페이지 제목과 주요 탭이 렌더링되는지 확인한다.
- CRUD 플로우 테스트: 사용자 또는 화학물질 화면에서 필수값을 입력해 등록하고, 조회 탭에서 검색 결과가 나타나며, 삭제 후 빈 상태 메시지가 표시되는지 확인한다.

## 운영 관점 메모

현재 구현은 과제/시연용 프론트엔드 프로토타입으로 보는 것이 정확하다. 실제 연구실 안전관리 업무에 사용하려면 법정 안전교육 이력, 화학물질/MSDS 관리, 폐기물 처리 기록, 점검 이력은 영속 저장과 감사 추적이 필요하다. 특히 삭제 기능은 실제 삭제보다 비활성화 또는 이력 보존 방식으로 바꾸는 것이 안전하다.
