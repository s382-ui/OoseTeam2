# 문서 유지보수 원칙

작성일: 2026-06-11

## 목적

문서가 커질수록 한 파일에 모든 규칙을 누적하지 않고, 주제별로 분리해 유지보수성을 높인다.

## 분리 기준

다음 조건 중 하나라도 해당하면 기존 문서에 계속 추가하지 말고 별도 문서로 분리한다.

- 한 문서가 150줄을 넘는다.
- 한 문서 안에 서로 다른 목적의 섹션이 4개 이상 생긴다.
- 특정 기능, 실행 방법, 테스트 방법, 배포 방법처럼 독립적으로 읽을 수 있는 주제가 생긴다.
- 문서 변경 시 관련 없는 섹션까지 자주 함께 수정된다.
- 에이전트가 작업 전에 읽어야 할 최소 문맥과 상세 참고 자료가 섞인다.

## 권장 문서 구조

- `docs/implementation-review.md`: 현재 구현 상태, 한계, 개선 방향
- `docs/run-guide.md`: 설치, 실행, 빌드, 실행 오류 대응
- `docs/agent-entry-documentation-policy.md`: 에이전트 진입 절차와 완료 기준
- `docs/documentation-maintenance.md`: 문서 분리와 유지보수 원칙
- `docs/reference_mdFileList/`: SRS, SDD, PMP, architecture 같은 원본 참조 문서
- `docs/<feature-name>.md`: 특정 기능의 상세 요구사항, 설계, 테스트 기준

## 작성 원칙

- 구현 사실, 참조 설계, 향후 계획을 구분한다.
- 문서 첫 부분에 목적과 적용 범위를 짧게 쓴다.
- 실제 파일 경로와 명령어를 정확히 쓴다.
- 긴 설명은 링크로 연결하고, 진입 문서에는 요약만 남긴다.
- 테스트가 없거나 실행하지 못한 경우, 구체적인 테스트 제안과 미실행 사유를 남긴다.

## 에이전트 적용 규칙

에이전트는 문서 변경 전 다음을 판단한다.

1. 기존 문서에 1-2문단만 추가하면 충분한가?
2. 새 주제가 독립적으로 읽혀야 하는가?
3. 기존 문서가 길어져 진입 문서로 쓰기 어려워지는가?

2번 또는 3번이 참이면 새 문서를 만들고 기존 문서에는 링크만 추가한다.

## 변경 예시

- 실행 방법 추가: `docs/run-guide.md`에 작성하고 `AGENTS.md`와 정책 문서에서 링크한다.
- 안전교육 상세 설계 추가: `docs/safety-education.md`로 분리하고 구현 리뷰 문서에서 링크한다.
- 테스트 전략 추가: 내용이 짧으면 `docs/run-guide.md`에 두고, 길어지면 `docs/test-guide.md`로 분리한다.
